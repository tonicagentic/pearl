# Pricing and terms

Price, discounts, and guarantees are the user's decisions. You structure
options and trade-offs; you do not choose numbers they have not given you.

## Before drafting

Confirm, or ask for, the unknowns that matter:

- The offer scope and delivery effort (hours, deliverables, duration).
- Any price the user already quoted or wants to anchor to.
- Buyer type and budget context, if known.
- Constraints: minimums, payment timing, currency, geography, taxes.

If none of this exists, ask one or two questions and stop. Do not fill in a
market-rate number from memory and present it as fact. If you cite a benchmark,
it must come from a source you found this turn.

## Options to present

Offer two or three structures with the trade-offs of each, such as fixed
project fee, retainer, usage- or outcome-linked, or a pilot followed by a
longer engagement. Show what the buyer gets at each tier and what the user
carries (risk, cash timing, effort). Use placeholders like `[price]` where the
user has not decided.

## Terms checklist

Scope and exclusions, deliverables and acceptance, timeline, payment schedule,
change requests, cancellation, IP and confidentiality, and liability limits.
Flag anything legal or tax related as something the user should have a
professional review. Do not give legal advice as settled.

## Output

Write pricing options or a proposal draft to a workspace file. If the Tempo
connection is available and the user wants the proposal recorded against a
deal, use the tools that connection exposes; any create or update is a write
that needs the user's approval. Otherwise leave it in the file.
