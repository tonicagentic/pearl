# Design principles

Apply these when briefing or critiquing a visual deliverable. Prefer concrete
revisions (what to change in the file) over taste adjectives.

## Checklist

1. **Hierarchy** — one primary focal point; secondary elements support it.
2. **Contrast** — enough value and size difference to read at the target size.
3. **Alignment** — edges and baselines share a clear grid; avoid accidental
   near-misses.
4. **Proximity** — related items group; unrelated items have air between them.
5. **Repetition** — reuse stroke weight, corner radius, and spacing so a set
   feels like one system.
6. **Palette** — keep it small; name colors as hex (or exact brand tokens). Do
   not invent a full brand system unless asked.
7. **Type** — exact wording, capitalization, and placement. Lettering that
   must stay precise belongs in SVG or HTML, not in a pictorial
   `generate_image` render.

## Critique

Judge against the brief and this checklist. Say what to change (stroke,
padding, color, size, crop), not only that it “feels off.”
